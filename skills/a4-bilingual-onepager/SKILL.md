# A4 双语一页纸制作（HTML + Chrome 无头打印）

路线一句话：**文案定稿 → 单文件 HTML 双页镜像模板 → 视觉设计四支柱 → 高度预算 + 无头 Chrome 逐轮校验 → 预览标注迭代 → 用户确认后才出 PDF**。

工程校验（第 3/4 步）保证「不出错」，视觉设计（第 5 步）保证「好看」——只做前者，成品会被评价为「设计感太差：配色素、排版平、没图示」。

为什么是 HTML 而不是 Figma / Word / 设计工具：

- 文字在 PDF 里保持矢量，改字号改文案不用重新导图；
- A4 尺寸 CSS 毫米级精确（96dpi 下 210×297mm = 794×1123px）；
- **版面能被程序测量**——这是本技能的核心：超没超高、字有没有被裁，用脚本读出来，不靠肉眼估。设计工具导出不可脚本化，Word 排版不可控。

## 产出物清单

```
onepager/
├── onepager.html      # 唯一模板：中英两页同源 + 全部文案 + 样式
├── build.sh           # 构建脚本（模板见 assets/build.sh.template）
├── fonts/             # 自托管字体（woff2），保证渲染确定性
├── preview-zh.png     # 中文预览（随库留档，diff 可比对）
└── preview-en.png     # 英文预览
../assets/             # 图片、logo、最终 PDF（../assets/ 相对路径引用）
<方案文档>.md           # 文案与版式的唯一事实源（HTML 是它的实现）
```

## 第 1 步：文案先行

先在方案文档里把每个区块的中英文案定稿（表格形式：| 中文 | English |），再写 HTML。原因：改文案比改版式便宜得多，而本流程里几乎每轮迭代都是「文案或版式微调 → 重建 → 校验」，有唯一事实源才能保证中英同步、改动可回溯。用户要求的特殊口径（如「不提具体门店数」「避免口语化」「某处英文不要改」）记入文档，防止后续改稿时回退。

## 第 2 步：模板骨架

```css
@page { size: A4; margin: 0; }
.page { width: 794px; height: 1123px; overflow: hidden; }
/* 中英两页在同一文件里，共用样式；差异用 .zh / .en 覆盖 */
body[data-lang="zh"] .page.en { display: none; }
body[data-lang="en"] .page.zh { display: none; }
```

- **双页镜像**：两页结构完全一致，只换文案；每处改动默认中英同步，除非用户明确限定单页。
- **单语言渲染**：模板里留 `__LANG__` 占位，build 时 `sed` 替换生成临时页再截图，一个文件出两页。
- **字体自托管**：中文栈（如 Hiragino Sans GB / PingFang SC）与英文栈（Inter woff2）各自固定，避免换机器行数变化。
- **设计令牌**：所有颜色放 `:root` CSS 变量（--navy / --muted / --amber-text …），改色只改令牌；色板与守则回写方案文档。

## 第 3 步：版面高度预算（核心纪律）

A4 内容区固定 1123px。**所有区块自然高度之和 ≤ 1123**，富余由唯一弹性区吸收。三条规则防「字被裁」：

1. **除弹性区外全部 `flex: none`**：`.page > *:not(.why) { flex: none; }`
   不写这条，flex 会把超高的内容**静默压缩**——区块变矮、`overflow: hidden` 裁掉文字，且不报任何错（Hero 定位句就是这样被裁掉半行的）。
2. **只留一个 `flex: 1` 弹性区**，且它的内容自然高度必须 ≤ 它实际分到的高度。
3. **定高元素（如 50px 页脚）加内容后必须复测** `scrollHeight ≤ height`——页脚从 2 行加到 3 行时就差点溢出。

每轮版式改动后跑测量（不靠眼睛）：

```bash
python3 scripts/measure_layout.py onepager.html
```

脚本跑两趟：

- **natural 趟**（强制 `flex:none + height:auto`）：各区块自然高度 + TOTAL vs 1123 → 回答「内容总共超没超」；
- **rendered 趟**（原样渲染）：页脚底 vs 页底差值、`overflow:hidden` 内 scrollHeight>clientHeight 的裁切点 → 回答「实际渲染有没有被裁 / 被顶出页外」。

硬门槛（任一不过就改版面，禁止导出）：

- natural TOTAL ≤ 1123（超出 → 收区块内边距/字号、或减内容）；
- rendered 页脚底与页底差 ≈ 0（贴底）；
- 无 CLIPPED 报告（有 → 该元素内容超高，收内容或改 min-height）。

## 第 4 步：打印可读性（PDF 发虚 = 对比度不够）

屏幕上「浅灰挺清楚」，导出 PDF 就没了——浅色墨覆盖率低。守则：**白底文字 ≥4.5:1、深底文字 ≥4.5:1、色块上的白字 ≥4.5:1**（WCAG AA）。

- 已知反例（写进文档防回退）：`#94A3B8` 白底仅 2.56:1（PDF 发虚）；`#F59E0B` 当白底文字仅 2.15:1；`#0EA5E9` 上白字 2.77:1。
- **装饰色与文字墨分离**：亮色可做色条/色块背景（`--bar`），一旦当文字用必须有加深版（`--bar-ink`）——卡片编号就是这样与色条解耦的。
- 每轮改色后跑：

```bash
python3 scripts/audit_contrast.py onepager.html --min 4.5
```

- 打印时背景默认会丢：`@media print` 里加 `* { print-color-adjust: exact; }`，否则渐变/色块背景在 PDF 里直接消失。

## 第 5 步：视觉设计（设计感四支柱）

工程校验保证「不出错」，这一步保证「好看」。最常见的差评是「设计感太差：配色素、排版平、全是文字没图示、不美观」——四支柱逐条解决。完整配色表、字号阶梯、可直接粘贴的 CSS/SVG 图示配方、图标集与评审清单见 **`references/design-playbook.md`**（改设计前先读它）：

1. **配色有骨架**：深蓝对角渐变 Hero（`--navy-ink → --navy → --blue`）压住头部；相邻区块背景在 白 / 浅带（`--surface`、`--tint`）之间交替，杜绝连续同底的「白墙」；琥珀只做点睛（编号徽章、关键数字、CTA、金句下划线），按底色分文字版（白底 `#B45309` / 深底 `#FBBF24`）；痛点用危险色浅底图标方块。**每页视觉锚点 ≥3 个**：深色 Hero + ≥1 个图示面板 + ≥1 条浅色节奏带。
2. **排版有层级**：字号阶梯 ≥4 级且相邻级差 ≥2px（金句 40/32 → 区块标题 14 → 卡片标题 10–12 → 正文 9–10 → 注释 7.5–8.5），字重只用 400/600/700；**所有区块标题共用一个模子**：琥珀渐变编号徽章 + 深蓝标题 + 右侧灰色注解；并列信息进卡片或多列面板，不要一排细线框平铺。
3. **内容图示化**：能画图的不堆文字——分层架构画「层板 + 左侧流向轨 + 末端箭头」，流程/闭环画「chevron 箭头块 + 虚线回流弧」，价值链画「卡片 + 箭头串联」，多角色画「单容器多列」（一个容器 = 一套数据的隐喻）；线性 SVG 图标 14–16px、stroke 1.5–1.8，**禁 emoji**；**缺图用等尺寸占位框**（虚线边 +「占位：xxx」标签，比例与最终素材一致），补图后回第 3 步测高。
4. **细节有质感**：圆角只用 6/8/10 三档、阴影只用一档 `--shadow` 令牌；装饰纹理透明度 ≤8%、绝对定位、mask 局部显影；细线框每页 ≤6 处，其余用浅阴影托底。

**设计评审**（并入第 7 步循环，排在机械校验之前）：预览出来先「缩到 25% 眯眼看」——层级是否一眼分明、锚点是否 ≥3、有没有真图示；再定点放大 4–5 处查模子/图标/间距一致性。清单见 playbook 第 5 节。**图示改动必须回第 3 步重测高度**（图比文字吃高度）。

## 第 6 步：素材处理

- 截图/照片缩到**显示尺寸的 4–10 倍**（打印 300dpi 余量）入库；**渐变类图片转 JPEG q86**（PNG 压不动连续渐变，实测 727KB → 31KB）。
- 每语言一个 logo（中文双语标 / 英文纯标），一律 `../assets/...` 相对路径。
- 素材来源与处理方式回写方案文档的素材表。

## 第 7 步：构建与验证循环

build.sh 约定（模板：`assets/build.sh.template`）：

- `./build.sh` → 中英 PNG 预览（迭代用）；
- `./build.sh --pdf` → 才导出 PDF，**只在用户确认定稿后执行**（PNG 是迭代产物，PDF 是交付物）。

每轮改动后的固定动作：

1. `./build.sh` 重建两页预览；
2. **设计评审（先于机械校验）**：按第 5 步 / playbook 第 5 节清单——缩到 25% 眯眼看层级与锚点，定点放大看模子、图标、间距；脚本只保证「不出错」，「好看」只有这一步能保证；
3. `python3 scripts/verify_preview.py preview-zh.png`（尺寸 / 页边距无渗出 / 内容非空白），英文页同样跑一遍；
4. **定点放大看改动处**：裁剪坐标必须来自测量探针的区块 y 值 + 页边距偏移——预览图含页边距（本模板上下各 24px），按估算坐标裁十有八九裁错位置，浪费一轮；
5. 整页过一眼：页脚完整、末行干净、无区块被顶歪；
6. 清理临时文件（`.build-*.html`、`zoom-*.png`、`check-*.png`、`.debug.html`）。

## 第 8 步：预览标注迭代（用户改稿的典型方式）

用户会在 HTML 预览上框选 + 评论（「这里太挤」「换成 X」「去掉」「英文版不要改」）。处理约定：

- 标注坐标是**浏览器视口坐标**，换算到预览图要加页边距偏移；拿不准就用探针量真实坐标，别猜；
- **一条标注一轮**：改 → 重建 → 定点验证 → 再下一条。一次改多条会互相掩盖问题，用户发现回归时无法定位是哪条引入的；
- 用户给了单页限定（如「英文版不要改」）只动指定页，其余一律**中英镜像同步**；
- 纯颜色/文案改动走第 7 步验证即可；**增删区块、改字号、改内边距、加图示必须回第 3 步重测高度**；涉及观感的改动（配色、排版、图示）还要过第 5 步设计评审。

## 第 9 步：最终导出与回写

1. 用户明确定稿 → `./build.sh --pdf`；
2. PDF 验收：每语言 1 页、A4 尺寸、背景与文字色齐全（print-color-adjust 生效）、文字可选中（矢量未栅格化）；
3. 回写方案文档：定稿文案、素材表、色板与守则、对齐记录——文档是唯一事实源，HTML 是它的实现，两边永远同步；
4. 提交时预览 PNG 随库留档，后续 diff 一眼看出版面变化。

## 常见坑（本流程真实踩过）

| 症状 | 根因 | 修法 |
|---|---|---|
| 文字被裁一半 | flex 静默压缩 + overflow:hidden | 所有区块 flex:none，只留一个弹性区 |
| 页脚不见/只剩一半 | 内容超高把定高页脚顶出页外 | 测 natural TOTAL；页脚加行后复测 scrollHeight |
| PDF 里浅灰字发虚 | 对比度 2.5:1 级 | 加深到 ≥4.5:1，跑 audit_contrast |
| PDF 里背景/渐变消失 | Chrome 默认不打印背景 | print-color-adjust: exact |
| 裁剪坐标全错 | 预览图含页边距偏移 | 坐标用探针量，不靠估 |
| 渐变图 PNG 几百 KB | PNG 压不动连续渐变 | 转 JPEG q86 |
| 中英改一边忘另一边 | 两页独立维护 | 默认镜像同步，除非用户限定单页 |
| 换机器行数变化 | 系统字体差异 | 自托管 woff2，中英各自 font-stack |
| 定稿后又想微调 | PDF 已是交付物 | 永远改 HTML → 重建 → 再导出，不手改 PDF |
| 页面素、设计感差（配色平/排版挤/没图示） | 只做了工程校验、没有设计步骤 | 走第 5 步四支柱 + playbook 配方与评审清单 |
| 加了图示后版面溢出 | 图比文字吃高度 | 回第 3 步跑 measure_layout，收别的区块或缩图 |

## 脚本

| 脚本 | 用途 | 何时跑 |
|---|---|---|
| `scripts/measure_layout.py <html>` | 两趟测高：自然总账 + 渲染态裁切/溢出 | 每轮版式改动后，导出前必跑 |
| `scripts/verify_preview.py <png>` | 预览图验收：尺寸/边距渗出/内容非空白 | 每轮重建后 |
| `scripts/audit_contrast.py <html>` | 抽取全部文字色，输出对白底/浅面/深底对比度矩阵 | 每轮改色后，导出前必跑 |

三个脚本均以退出码表达结论（0=通过），可直接串进构建流程。
