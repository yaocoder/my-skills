# PPT Pipeline — 代码化 PPT 生成流水线（方法论，无内置视觉规范）

## 核心理念

1. **代码优先，不用模板**：每页坐标、色值、线宽全部精确可控。本技能**不内置任何默认色板、默认字体、默认页面骨架**——设计系统由每个项目现场定义（见 Step 2）。
2. **原生图形画图**：架构图/流程图/时间轴/飞轮一律用 PPT 原生形状绘制（可编辑、不失真），禁止把图渲染成图片贴入。
3. **渲染回看是强制环节**：生成后必须把每一页渲染成图片逐页目检，修复后复验。只生成不检查 = 未完成。

## 开工前输入清单

向用户确认或从上下文获取（缺什么问什么，不要臆造）：

- [ ] 内容来源（文档/大纲/要点清单）
- [ ] 受众与目的（高层汇报/客户提案/内部评审）
- [ ] 页数（正文 + 附录分开算）
- [ ] **设计系统来源**：项目文稿若带有「全局视觉与设计规范」章节，直接照其执行；否则向用户要 VI/品牌规范（主色、辅助色、字体、底色、页骨架）；都没有 → 与用户现场协商一版，写进 build 脚本，**不要使用任何“技能默认配色”**
- [ ] 硬性约束（禁用词/不得出现的品牌·金额·内部编号/Logo 授权）
- [ ] 图片素材位置（真实图优先于生图；生图可先用占位框）

## 工作流

```text
Task Progress:
- [ ] Step 1 解析来源，产出「逐页页面清单」（标题=结论句、要点、图/表形式）
- [ ] Step 2 按项目输入定设计系统（色板/字体/栅格/骨架函数）写入 build 脚本头部
- [ ] Step 3 逐页编写生成脚本（复用 scripts/pptx_kit.py 中性工具）
- [ ] Step 4 生成 + 程序化自检（禁用词、敏感数字、页数）
- [ ] Step 5 渲染逐页目检 → 修复 → 复验（scripts/render_check.py）
- [ ] Step 6 交付并说明可复跑方式
```

**Step 1 · 页面清单**：每页记录五项——结论式标题 / 正文要点 / 图或表的类型 / 素材来源 / 金句(可选，与否由设计规范决定)。标题必须是判断句，不是名词短语（❌「产品介绍」✓「一台会看、会听、还会看病气色的终端」）。

**Step 2 · 设计系统（按项目自定，技能零预设）**：
- 实现方式：在项目 build 脚本头部定义本项目色板常量与骨架函数（封面/内容页的眉题、标题、分隔线、页脚、页码等），并在 import kit 后调用 `K.configure(cjk="…")` 声明本项目中文字体；
- 若文稿带「全局视觉与设计规范」（主色/辅助色/字体/栅格/句式规则表），逐条映射为脚本常量与骨架函数；两者冲突时以文稿规范为准；
- 关键技术：中文字体必须通过 XML 设置 `a:ea`（东亚字体）才生效，python-pptx 的 `font.name` 只管西文（kit 的 `set_run` 已处理）。
- 示例参考：[reference.md](reference.md) 收录了一套**历史项目的示例色板/骨架**，仅供格式参考，不是默认值。

**Step 3 · 编写**：先 `import` 技能包里的 `scripts/pptx_kit.py`（或复制其中函数进你的脚本），再逐页写布局。所有循环必须有坐标递增语句。kit 只提供中性工具（形状/文本/连线/图片/自检），所有颜色由你的项目代码显式传入。

**Step 4 · 自检**：生成后用 python-pptx 回读成品，检索禁用词与敏感数字（脚本模式见 reference.md）。

**Step 5 · 渲染目检（不可跳过）**：
```bash
python3 scripts/render_check.py 输出.pptx --out ./pages
```
逐张查看 PNG，按下方「常见版式 bug 清单」排查，修复后重跑 Step 4–5。

**Step 6 · 交付**：告知成品路径、复跑方式、遗留问题（需人工处理的水印/授权/命名等）。

## 工程硬规则（方法论，不含视觉主张）

**必须做**
- 关闭所有形状默认阴影（`shape.shadow.inherit = False`，kit 的 rect/arrow 已处理）
- 页面常用 16:9（13.333×7.5 in）；统一栅格：左右页边距一致、卡片列间距与坐标递增一致
- 每页复用同一骨架函数（由项目脚本定义），保证眉题/标题/页脚/页码一致
- 图片先用 PIL 中心裁剪（cover）到目标框比例再插入，杜绝拉伸
- 循环内所有 x/y 必须有显式递增语句；末列右边界 = 起点x + 列宽×n + 间距×(n-1) ≤ 内容宽

**禁止做**
- ❌ 架构图/流程图/时间轴用图片渲染贴入（除非用户明确要求生图）

## 流程图 / 架构图画法经验（实战沉淀）

以下是多轮真实项目验证过的做法，画图前先读一遍，可少走一轮渲染目检弯路：

**流程链（生命周期 / 多步骤长链）**
- 9+ 步的长链不要用一排 CHEVRON 硬挤——先把节点按业务阶段**分组**：每组一条浅色圆角色带垫底，带下居中放组名（如 数据域 / 模型域 / 交付域）；平台真正补齐的分段节点填主色反白，视觉叙事自动成立。
- 节点间箭头用小号 `RIGHT_ARROW`（≈0.11×0.18）居中对齐节点中线，不要用文本「›」充当（对不齐、字距不可控）。
- 「闭环」不是口号：至少画 1–2 条**回流虚线**（如「评估不达标 → 回数据治理」「设备回执 → 反馈迭代」），走节点行下方的空带横穿，标签 8pt 写在横走段下方。没有回流的流程链不叫闭环。

**回流虚线的走线（bug 高发区）**
- 一律用三段直线连接器：从源节点底部中心下出 → 横走（走卡片**外侧**空带，严禁斜穿卡片）→ 垂直回目标节点底部末段带箭头；三段分别 `dashed()`，只有最末段 `arrow=True`。
- 两条及以上回流要分层错开 y（如 3.95 / 4.3），标签也分层放置，避免文字压线。

**分层架构图**
- 每层一张宽卡：窄标题列（层名 + 7.5pt 技术栈副标）+ 宽 chip 行（层内模块）布局，比「层名+一句话描述」的纯文本条信息密度高且专业感强；chip 行用 `MSO_ANCHOR.MIDDLE` 垂直居中。
- 层间不放裸箭头：`DOWN_ARROW` 旁必须配**层间契约标注**（HTTP/REST·JWT、任务表·状态回写、SQL·S3 SDK）。契约标注让架构图从「叠积木」升级为「工程图」。
- 层内模块若多（crt_/bld_/hub_/dep_ 这类），放 chip 里 7pt 也比挤在描述句里清晰；中英文/代码名 chip 混排时 chip 宽 ≥1.2。
- 架构图旁边尽量配一张**现网实拍截图**（如执行节点管理页），「逻辑分层 → 部署形态 → 真实运行」三段式最有说服力。

**页面级模板语法（方案型 PPT 高频复用）**
- **资产飞轮**：厚环背景（外圆辅助浅色 + 内圆挖空成环）+ 中心白圆主题（主色标题 + 副题，金细描边）+ 四方位实心卡（北/南主色、东浅主色、西辅助色，各含标题 12pt 反白 + 8.5pt 副行）+ 环上 4 枚金色小三角表示旋转方向（放在 45/135/225/315 四方位，尺寸 ≈0.26）+ 右下 9.5pt 灰注解。适合表达「越用越厚/复利/闭环增值」类叙事。
- **对比双面板 + 大≠**：左浅灰面板放「旧认知/传统做法」、右主色深底面板放「新认知/我方做法」，**同维度逐行对仗**（标签列 + 描述列，行高一致），行首标签左灰右金；两面板间居中放一个大号「≠」或「→」（30pt 辅助色）。痛点页、定位纠偏页首选此结构，说服力远高于 bullet 列表。
- **S 形闭环流程**（6 节点版）：分带眉注（左灰右主色两条 9.5pt 标签 + 一条 0.75pt 细线）+ 上排三节点（白底）左→右金色 `RIGHT_ARROW`(0.4×0.34) + 下排三节点（**主色深底反白**）右→左灰色 `LEFT_ARROW` + 右列行间金色 `DOWN_ARROW`；回流虚线走**左外侧**三段式，回流标签居中写在第二排下方。九步长链可归并为六段宽卡（每卡「①标题行 + 8.5pt 副行」），比 nine-chip 密排更透气。
- **关键词卡**：卡片标题下加一条 0.45×0.028 辅助色短划线；**必须同时给正文让位**（正文 space_before 需 ≈12，否则划线压首行——目检必查）。
- **深浅分区三卡**：核心项一卡填主色反白、其余白卡描边；卡顶 0.1 倍列宽的彩条不如「题下短划线」耐看；三卡后接一条虚线细线 + 一排组件 chip（等宽 ≈2.86、ZEBRA 底、主色文字），把「由哪些系统组成」收底。
- **全宽结论横幅**：关键总结句可以做一条深主色满宽带（12.5pt 反白加粗居中），比金句带更重；每页至多一条，压在内容区底边之上。
- **段带眉注**：一条 0.75pt 细线的左右两端各放一条 9.5pt 标签（左灰=通用区、右主色加粗=强调区），比两侧贴 chip 更轻，适合给流程/表格分段定性。

**通用细节**
- 节点/卡片内的强制换行：不要往 run 里塞 `\n`，逐段 `para()` 追加。
- 深色层/卡上的次级文字用「纸白」（PAPER_TX 类）而不是纯白，主信息才够跳。
- 分组色带先画、节点后画：z-order 即绘制顺序，不要靠事后挪动补救。
- 用 `add_shape` 裸加的形状（OVAL/DONUT/三角形等，未经 kit 的 rect/arrow 包装）也必须手动关闭 `shape.shadow.inherit = False`，否则 PowerPoint 渲染出默认阴影。
- 中途插入新页时，后续页码参数（page_no）与注释标题按**降序批量替换**（如先 18→19 再 17→18），避免升序替换造成的连锁覆盖。

## 常见版式 bug 清单（目检重点）

| 症状 | 典型病因 |
|---|---|
| 多列只显示一列/全叠在左侧 | 循环里缺 `x += 步长` |
| 形状出血到页面外 | 列宽×列数+间距 > 内容宽度，末列 x 计算漏加间距 |
| 虚线/箭头穿过卡片 | 回流线没走卡片外侧通道 |
| 元素压住标题/页脚/金句带 | 纵向范围侵入标题带或底部带，改坐标 |
| 文字压住细线 | 文本框底边与细线的 y 间距 < 文字行高 |
| 表格下注释叠行 | 注释 y 未按「表头+行高×行数」重新计算 |
| 中文渲染成宋体/西文字体 | 没设 `a:ea` 东亚字体 |
| 卡片题下划线压住正文首行 | 装饰划线没给正文让位——正文 space_before ≥12，或划线改画在标题上方空隙 |
| 环形飞轮的旋转三角方向不一致（一半顺一半逆） | 极角参数化不对称——必须按 bearing（自正北顺时针）放置：x=cx+R·sin θ、y=cy−R·cos θ、rotation=θ+90（等腰三角默认朝北）；用 cos/sin 混排 + 统一 +90/+270 都会造出镜像箭头 |
| 修改模块常量后底色没变 | Python 默认参数在函数定义时绑定——骨架函数须在常量定义之后、显式传色 |
| 图片变形 | 直接 add_picture 指定 w+h 而未先 cover 裁剪 |

## 脚本用法

- `scripts/pptx_kit.py`：**中性技术函数库**——页面尺寸常量、文本（含 `a:ea` XML 字体）、矩形/细线/虚线箭头/箭头形状/chip/占位框、图片 cover 裁剪、自检。内置**零色板、零字体预设**；使用前调用 `K.configure(cjk="…")` 声明项目字体，所有颜色由项目代码显式传参。
- `scripts/render_check.py`：导出渲染管线，按优先级自动选后端：LibreOffice(soffice) → macOS PowerPoint(AppleScript) → qlmanage(仅封面)；再用 pypdfium2 把 PDF 逐页转 PNG。执行：`python3 scripts/render_check.py deck.pptx --out ./pages`。
- `examples/minimal_deck.py`：最小可运行示例——**演示“项目自定设计系统 + 中性工具”的正确姿势**（本地色板常量 + 本地骨架函数 + configure），直接 `python3 minimal_deck.py` 验证环境。

依赖：`python-pptx`、`Pillow`、`pypdfium2`（均 `pip install` 可得）。
