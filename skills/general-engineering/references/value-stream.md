# 价值流对齐（仓内投影）

组织级价值流（准备 → 交付 → 运营）是坐标系。本技能只落实**能 as-code 的承载面**。

不要把价值评审会、看板纪律、业务数据分析做成必生成文档。

## 映射表

| 阶段 | 仓内应对（做） | 只留接口（不做空仪式） |
|------|----------------|------------------------|
| 需求 | `docs/产品/` 或 `docs/需求/` 槽位；故事/范围模板可选；交付标准（DoD） | 价值评审流程、立项会议纪要制度 |
| 开发 | 骨架、ADR、本地 DX、代码检查入口、单测槽位、集成构建（CI） | 任务拆到哪张看板 |
| 测试 | 功能测试入口；CI 分层；可选性能目录标 planned | 强制混沌工程、一上来就压测套件 |
| 验收 | DoD；里程碑证据链（计划→脚本→记录）；align-audit 缺口清单 | 替代正式 UAT 技能去写角色矩阵 |
| 发布 | `deploy/` 契约、`ops/` 编排、verify/rollback、制品分轨原则 | 未有移动端却写灰度方案全书 |
| 运营 | 健康检查、指标槽位、运维 runbook 索引 | IaaS/PaaS 全套、业务经营分析 |

## 管理体系三句

- **看板**：技能外。最多一句话建议列与阶段对齐。
- **自动化**：CI + start/stop + deploy/ops = 仓内投影。这是本技能主场。
- **数字化**：审计包与 CI 结果可供组织引用；不在仓内造 OKR 大屏。

## 证据链（贯穿交付期）

```text
计划或 ADR → 过程记录（可选）→ 可跑验收（脚本/测试名）→ 完成说明 → 延期清单
```

过程记录进 `docs/交互记录/` 或等价过程层，不替代 `docs/` 正式规格。
