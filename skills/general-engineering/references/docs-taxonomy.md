# 文档 taxonomy 与索引

文档当产品养：分类按性质，导航只有一个索引。

## 目录

| 目录 | 放 | 不放 |
|------|----|------|
| `docs/产品/` | 能力真相、路线图、术语、闭环总览 | 短问答、过时快照 |
| `docs/架构/` | 分层、边界、状态机 | 实施 checklist |
| `docs/决策记录/` | 已采纳 ADR | 头脑风暴 |
| `docs/运维/` | 安装升级、备份、指标、脚本矩阵 | 产品路线图 |
| `docs/需求/` | 可选：范围、故事、DoD | 替代产品 SSOT 的营销稿 |
| `docs/参考资料/` | 外部材料、差距快照 | 当前 SSOT |
| `docs/归档/` | 过时快照、完成波次 | 仍生效的能力说明 |
| `docs/问答/` | 仅用户点名「问答」 | 矩阵、白名单、能力 SSOT |

英文别名可并存：`product` `architecture` `adr` `ops` `faq` `reference` `archive`。同一仓选定一套，不要中英各建一套重复树。

## 三层隔离

1. **正式** `docs/` — 权威
2. **过程** `docs/交互记录/` 或 `过程交互文档/` — 为何、讨论、证据链
3. **工具草稿** `.superpowers/` 等 — 不混进正式树

## 索引

文件：`docs/文档索引.md`（若已有 `docs/README.md` 当索引，不要再复制一份）。

索引必须含：

- 路径 · 一句话用途 · 状态（现行 / 归档）
- 角色入口（新人 / 开发 / 运维）各若干条
- 维护句：增删改路径必须改本页

## DoD 放哪

短清单放 `docs/需求/交付标准.md` 或 `docs/产品/交付标准.md`，并在 README 与 AGENTS.md 链接。条目要可检查（测试命令、CI job 名、verify 脚本），不要「代码质量良好」这类空话。
