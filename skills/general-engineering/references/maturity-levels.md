# 成熟度级别

本技能用级别防止一次铺满空壳。先定级，再选交付物。

## L0 可跑（新仓默认目标）

人与 Agent 能在本机按文档把栈拉起来（或清楚知道「还没有可运行代码、只有承载面」）。

必须有：

- 可读的根 README（结构 + 入口命令 + 文档索引链接）
- 目录骨架（空模块标 planned）
- `.gitignore` 排除密钥与本地状态
- `.env.example`
- 文档分类 + 唯一索引（可先薄）
- `AGENTS.md` 命令表（哪怕命令是「尚未实现 start.sh」）

没有 L0，后面的 CI/生产包都是表演。

## L1 可交付（整顿时优先补的下一档）

能把**某一条环境线**交给测试或演示，并且知道如何验收、如何回滚意图。

必须有：

- 本地 start/stop（或等价 compose 一键）与日志目录约定
- env 分层：example 进 git；prod 拒绝默认口令的门闩或至少文档 + 启动检查
- CI 最小接线：至少一种真实检查（单测或 typecheck 或结构校验）；guard 雏形
- 测试槽位：单测入口写清；功能/UAT 入口或「交给 uat-tester」
- DoD / 交付标准（短清单，可检查）
- deploy 路径契约 + verify/rollback 说明（脚本可为 stub）
- 至少 1 条 ADR 解释形状（单体 vs 多服务、编排 vs 执行进程等）

L1 不等于生产就绪。

## L2 可运营（默认不在 bootstrap 强求）

生产线和演示线分离；观测与审计能复盘事故。

通常有：

- demo/clean 或 staging/prod 双环境
- 制品分轨（测试制品 ≠ 生产制品）原则写进运维文档
- 应用级健康 + 指标槽位；告警 runbook 链接
- CI guard 必绿（安全/隔离/静默故障类）与植入回归证明
- `.audit/` 不是空 README，而是请 `production-readiness-audit` 产出的证据包
- 密钥双路径与轮换 SOP

IaaS/PaaS 监控、压测、混沌、灰度：L2+ 可选项，用户点名再做。

## 对照口诀

| 问句 | 级别 |
|------|------|
| 新人按 README 能下手吗？ | L0 |
| 能交给测试环境并说清何为完成吗？ | L1 |
| 敢用独立于 demo 的姿势上生产并回滚吗？ | L2 |

跳级（空仓直接 L2 全家桶）禁止。那正是虚假成熟度。
