# 文档维护规范

| 项 | 内容 |
|---|---|
| 适用范围 | 本仓库 `docs/` |
| 真相源 | git 内 Markdown；Wiki / 静态站只渲染 |
| 更新日期 | YYYY-MM-DD |

## 1. 总原则

1. 一份真相：现行结论只写在现行文件；禁止「新版-xxx」与旧版长期双主线。
2. 三层分离：正式规格 · 对外材料 · 过程沉淀。
3. 先定目录再落笔：读者是研发/运维、客户/合作方，还是仅本次会话。
4. 代码行为变了：同步改对应正式文档；重要「为什么」写入过程记录。

## 2. 新增：放哪里

按本仓库真实目录填表（示例列）：

| 内容类型 | 目录 | 命名 |
|----------|------|------|
| 架构 / API / 部署 | （填本仓路径） | 序号或主题 |
| 答疑 | `Q&A/` 或等价 | `YYYY-MM-DD-主题.md` |
| 会话落地 | 按月目录 | `YYYY-MM-DD-主题.md` |
| 上游原文 | `reference/`（若存在） | 不放本项目决策 |

新建正式页后：更新该目录 README；若进 Wiki 主导航，同时改 `docs/.vitepress/config.mts`。

## 3. 更新：改旧还是新建

| 情况 | 做法 |
|------|------|
| 仍现行，只修错 | 原地改 |
| 方案被替代 | 迁 `_archive/`，现行文档改链 |
| 同主题短记堆积 | 合并或并入正式手册 |
| 序号撞车 | 新文用下一空号并修断链 |

禁止在 Wiki 后台 / Notion 另改正文再「有空同步」。

## 4. 工作流

改代码或定需求 → 改 docs 正式页 → 更新 README → 必要时改 sidebar → 同一 PR → CI `docs:build`。

本地：`./start-wiki.sh`（推荐）或包管理器 `docs:dev`。

## 5. Wiki

- 配置：`docs/.vitepress/config.mts`
- 第一期不做公网 Pages / 生产子路径，除非产品明确要求
- 密钥真值、未脱敏排障不进可公开构建物

## 6. 检查清单

- [ ] 分层与目录正确
- [ ] README / 总索引已更新
- [ ] 需要进主导航时已改 sidebar
- [ ] 相对链接可打开
- [ ] 过时正文已归档而非双主线
- [ ] 无密钥、密码、token
